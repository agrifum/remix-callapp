# TECHNICAL_SOURCE_POLICY

ENV-2. Ta polityka zapewnia ścieżkę researchu wewnątrz projektu; nie uruchamia researchu aplikacji przez zewnętrznego opiekuna.

Priorytet: aktualna oficjalna dokumentacja → oficjalne repo/kod → aktualna dokumentacja Context7 → uzasadnione wiarygodne źródło wtórne. Pamięć modelu nie jest dowodem szybko zmieniającego się API.

Przy autoryzowanym pytaniu projekt określa potrzebne źródło, wersję/kanał i datę sprawdzenia. Oddziela documented fact, inference i unknown oraz zapisuje URL, zakres twierdzenia i ograniczenia. Nie aktualizuje zapisów specyfikacji tylko dlatego, że istnieje nowa wersja narzędzia.

SOURCE_REGISTRY jest katalogiem punktów wejścia, nie weryfikacją stosu aplikacji. Jeśli Knowledge Base daje wystarczającą autorytatywną odpowiedź, nie powielaj jej dodatkowymi narzędziami. Context7 służy konkretnemu pytaniu o bibliotekę po wyborze jej library ID. Nie przesyłaj prywatnych danych produktu do wyszukiwarki.

Decyzje o aplikacji, jej wykonaniu, wersjach i ewentualnych konfliktach podejmuje projekt. Zewnętrzny opiekun może opisać dostępne mechanizmy środowiska i organizację źródeł; nie ocenia treści instrukcji użytkownika.

## 1. Executive Summary & Mandatory Deep Checks

This audit provides a fresh, evidence-based static baseline assessment of the CallUpp repository at commit `acf2cf1f88bc9f6db8ca52c4e4619b16634890f7` against all 68 specification sections (`SP-001` through `SP-068`) defined in `docs/core/MASTER_SPEC.md`.

### Mandatory Deep Checks Overview

| Check Item | Status | Key Finding / Locator |
|---|---|---|
| **JVM 17 / SDK configuration** | PASS | `compileSdk = 36` (minor 1), `targetSdk = 36`, `minSdk = 31`, `sourceCompatibility = JavaVersion.VERSION_17`, `targetCompatibility = JavaVersion.VERSION_17` in `app/build.gradle.kts#L9-L51`. Built with AGP 9.1.1, Kotlin 2.2.10, Gradle 9.3.1. |
| **Hilt requirement vs actual DI** | FAIL | Spec §2 mandates Hilt. Synchronous flush on call end (`flushAndStop`) cancels debounce and pulls latest in-memory draft. State machine in `CallDraftRepository.kt` (`IDLE_ALLOWED`, `AUTO_IN_PROGRESS`, `MANUAL_IN_PROGRESS`, `COMMITTED`) with per-session mutex prevents race conditions between user save and call termination. |
| **Call-end note preservation** | PASS | Unsaved draft note text is automatically converted to `NoteEntity(source = CALL)` on `IDLE` in `CallDraftRepository.kt#L218-L248` without auto-creating Client, Job, or Task. Verified by 10 unit tests in `CallDraftCommitIdempotencyTest.kt`. |
| **Critical Room transactions** | PARTIAL | Overlay save (`commitOverlaySession`) runs in `database.withTransaction` covering Note, Client, Job, Window, Task, and draft deletion. AI address acceptance runs in `database.withTransaction`. AI term acceptance transaction lacks Calendar update and worker rescheduling. |
| **Job entities/status/window behavior** | PASS | `JobEntity.kt` matches specification (ACTIVE, COMPLETED, CLOSED, `isArchived`, `deletedAt`, snapshots, qualifiers). Status transitions properly manage `JobAnalysisWindowEntity` records. Soft duplicate term check implemented in `JobRepository.kt#L147-L160`. |
| **+24h scheduling and reconciliation** | PARTIAL | Anchor calculation in `JobRepository.kt#L169-L182` and periodic 6h `JobStatusReconciler.kt` are implemented. Dedicated event-driven one-shot `AutoCompleteJobWorker` at anchor+24h and worker cancellation/rescheduling on term edit are missing. |
| **Reopen and new-job semantics** | PASS | Reopen sets status to ACTIVE, records `reopenedAt`, and opens a new analysis window (reason = REOPENED). `ReengagementRepository.createNewJobFromPrevious` copies client, address, service, price; leaves term and summary empty. |
| **SMS trigger/worker/raw-content handling** | PARTIAL | Raw SMS content is NEVER persisted to Room; `SmsTriggerEntity.kt` stores metadata only. However, `SmsReceiver.kt#L67` runs extraction in `appScope.launch` rather than delegating to a WorkManager `SmsAnalysisWorker`. |
| **AI boundary and field protection** | PASS | `SmsExtractionInput` minimizes payload. Existing client address and job terms are never overwritten automatically; changes generate `AiSuggestionEntity` records (ADDRESS_CHANGE, TERM_CHANGE). Fail-closed error handling in `SmsAnalysisCoordinator.kt#L121-L132`. |
| **Reengagement** | PASS | `ReengagementRepository.kt` detects incoming call/SMS when client has no active jobs but prior completed/closed jobs. Creates max 1 PENDING `ReengagementEventEntity`. `ReengagementDialog.kt` provides Wznów, Nowe zlecenie, Ignoruj. |
| **Calendar implementation** | FAIL | Permissions declared in manifest; `JobEntity.calendarEventId` and `AppPreferences.preferredCalendarId` exist. Actual `CalendarContract` ContentResolver operations (insert, update, delete) are completely missing. |
| **CallLog filtering** | PASS | `CallLogRepository.kt#L138-L177` queries system ContentResolver directly without copying log to Room. Strictly filters entries to numbers with an existing ClientEntity or NoteEntity. |
| **Telephony signal path** | PARTIAL / UNKNOWN | `CallScreeningServiceImpl.kt` captures call details and responds immediately. `CallStateMonitor.kt` registers `TelephonyCallback` on API 31+ and triggers overlay directly on `CALL_STATE_OFFHOOK`. However, per Android documentation and research (RSCH-TELEPHONY), `CALL_STATE_OFFHOOK` occurs at the start of outgoing dialing (not remote-party answer/active conversation), meaning exact outgoing-answer detection cannot be statically claimed without default dialer replacement. |
| **Required/forbidden permissions** | PASS | All 12 required permissions declared in `app/src/main/AndroidManifest.xml#L6-L25`. None of the 7 forbidden permissions are declared. |
| **UI screens / navigation** | PARTIAL | Bottom bar has Połączenia, Zlecenia, Zadania. Uses Navigation 2.8.9 rather than Navigation 3. Missing UI screens: Szablony SMS, Onboarding wizard, multi-selection on Jobs, and several detail sub-sections. |
| **Trash / retention** | PASS | Soft delete (`deletedAt`), 30-day retention, `TrashScreen.kt` with restore and permanent delete, and periodic `TrashCleanupWorker.kt` (24h periodic WorkManager). |
| **ETA / navigation** | PARTIAL | Google Maps intent launched via `google.navigation:q=<address>`. Passive ETA extraction in `MapsNotificationListenerService.kt`. Manual ETA fallback picker is missing. |
| **Mandatory test coverage** | PARTIAL | Automated tests verify CallDraft commit idempotency and race handling (10 tests). Unit tests for SMS AI, AI field protection, Client, Jobs, Calendar, Navigation, and Bulk operations are missing. |
| **DoD items remaining runtime-only** | NOT_TESTABLE_STATICALLY | SP-066 requires 20 verification criteria on a physical Android device across telephony lifecycle, window overlays, and IME behavior. |

### RUNTIME UNKNOWNS

1. **SP-066: Definition of Done v1 On-Device Criteria**
   - All 20 DoD operational criteria require execution on a physical Android device with a cellular SIM card.
2. **SP-008, SP-061, SP-062: WindowManager Overlay & Soft Keyboard Handling**
   - Behavior of `FLAG_NOT_FOCUSABLE` flipping to focusable upon note touch, IME appearance, and touch-outside dismissal requires validation against actual Android system window managers, particularly OEM variants (e.g., Xiaomi HyperOS / Samsung OneUI).
3. **SP-044: Google Maps Notification Parsing**
   - Regex matching of ETA text patterns (`min`, `godz`) from status bar notifications requires runtime validation against active Google Maps turn-by-turn navigation sessions.
4. **SP-049 & SP-008: Outgoing Call Dialing vs Active Answer Distinction**
   - On Android 12+, non-default-dialer apps only receive `CALL_STATE_OFFHOOK`, which fires immediately upon outgoing dialing start (not remote-party answer). Statically distinguishing dialing from active conversation is impossible without InCallService / default dialer role. On-device timing and UX impact must be evaluated.

1. **Navigation 3 / Room 3 Stability & Tooling Support**
   - Status of Navigation 3 (1.1.x) and Room 3.0.x multiplatform/KSP integration on the current Gradle 9.3.1 / Kotlin 2.2.10 toolchain.

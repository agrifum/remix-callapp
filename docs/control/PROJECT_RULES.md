# PROJECT_RULES

ENV-2. Nadrzędna granica roli: ENVIRONMENT_BOUNDARY.md.

1. Oryginały użytkownika i późniejsze jawne decyzje w projekcie mają pierwszeństwo. Parafraza opiekuna nie może ich zastąpić.
2. MASTER_SPEC, SP, SW i EX są zachowanymi źródłami. Opiekun nie edytuje ich treści w zadaniu utrzymania środowiska.
3. Cała merytoryczna praca aplikacyjna należy do zamkniętego projektu. Opiekun nie identyfikuje ani nie rozstrzyga problemów aplikacji i nie narzuca blokad.
4. Projekt czyta właściwe źródła przed decyzją. Nie rekonstruuje ich z pamięci; odnotowuje brak niezbędnego kontekstu.
5. Gdy projekt podejmuje autoryzowany research, rozdziela dokumentację techniczną od wymagań. Dowód HOW nie zmienia samoczynnie WHAT.
6. Rejestry decyzji i pytań zasilają rzeczywiste ustalenia projektu. Puste rejestry nie oznaczają oceny kompletności aplikacji.
7. Używaj małych context packs i ogólnych szablonów. Nie kopiuj całej historii do każdego promptu ani specyfikacji do Rules.
8. Nowa materialna decyzja projektu wymaga spójnej aktualizacji dokumentów i statusów zależnych promptów. Zachowaj historię źródła.
9. Narzędzia, Skills i MCP dobieraj do potrzeby środowiska; nie instaluj dodatków ani nie uruchamiaj wykonawcy dla samej dostępności.
10. Kontrola opiekuna obejmuje integralność dokumentów, spójność publikacji i organizację projektu. Nie jest testem ani oceną aplikacji.
11. Nie przechodź automatycznie z utrzymania środowiska do tworzenia promptów lub budowy. Te działania należą do projektu i jego właściwego zlecenia.

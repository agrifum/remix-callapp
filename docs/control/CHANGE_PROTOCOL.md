# CHANGE_PROTOCOL

ENV-2. Rozdziel zmiany środowiska i zmiany merytoryczne.

## Opiekun środowiska

Może poprawić organizację, metrykę, instrukcje swojej roli, szablony ogólne lub publikację. Zachowuje niezmienione oryginały. Nie oznacza własnej korekty jako nowej wersji aplikacji. Wycofane opracowania trafiają do jawnego archiwum bez prawa wykonania. Publikuje spójne paczki, usuwa zastępowane kopie i sprawdza ich obecność.

## Decyzje w zamkniętym projekcie

Projekt zapisuje rzeczywistą decyzję użytkownika z datą i lokalizatorem. Określa wpływ na specyfikację roboczą, historię decyzji, źródła, pytania, CP oraz rejestry promptów. Oryginał pozostaje niezmienionym dowodem; przyszła specyfikacja robocza powinna jawnie wskazywać różnice i ich autoryzację. Nie zastępuje się oryginału po cichu.

Zależne nieaktualne prompty nie zachowują READY. Nie kasuje się historii. Jeśli istnieje autoryzowane wykonanie, projekt ustala handoff zmiany. Zewnętrzny opiekun nie podejmuje takiej decyzji samodzielnie.

Synchronizacja plików jest obowiązkiem organizacyjnym, nie zainstalowaną usługą ani automatem. Sprawdzenie publikacji nie stanowi oceny aplikacji.
